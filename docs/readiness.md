# Готовність до захисту та сценарій показу

## Перелік готовності

Статус «перевірено» означає, що сценарій фактично виконано.

| Перевірка | Статус |
|---|---|
| Вимоги | Перевірено вручну: каталог навичок, створення, перегляд, редагування, видалення кейсів, пошук, фільтр, сортування працюють як один сценарій |
| Запуск | Перевірено: `npm install`, `npm run dev`, `npm run preview`; команди описані в README |
| Git і Docker | Історія одного проєкту з гілкою на кожну лабораторну; Docker-запуск налаштовано в Л 1.1 і в цій роботі повторно не перевірявся |
| Компоненти | Спільні `FormField`, `AppButton`, `Section`, `EmptyState`, `CaseForm` використовуються і для створення, і для редагування |
| Стан | Один знімок кейсів у `CasesProvider`; чернетка форми окремо; фільтри в URL |
| Маршрути | Перевірено тестами й вручну: параметри, переходи, невідома адреса, невідомий кейс |
| CRUD | Перевірено тестами й вручну; видалення лише після підтвердження |
| Форми | Помилки біля полів, повторне подання заблоковане на час запису |
| Стани даних | Завантаження, помилка з повтором, порожня колекція й відсутність збігів розрізняються |
| Відновлення | Повтор читання працює; відмова запису не знищує введення |
| Сервіси | UI залежить лише від `caseService`; режим джерела описано в README |
| Тести | 45 тестів проходять (`npm run test:run`) |
| Якість коду | `npm run lint` без зауважень |
| Продуктивність | Виміряно в dev-режимі, висновок у `component-architecture.md` |
| Build | `npm run build` і `npm run preview` виконано |
| Доступність | Поля мають доступні назви (тести знаходять їх за роллю), помилки текстові, форма доступна з клавіатури |
| Конфігурація | У `VITE_` змінних немає секретів; за замовчуванням режим mock |
| Захист | Сценарій показу нижче |

## Сценарій показу (3–5 хвилин)

1. Пояснити задачу: портфоліо для відстеження прогресу в дата-аналітиці; навички лише для читання, кейси з повним CRUD.
2. Відкрити каталог навичок і перейти до створення кейсу для навички.
3. Подати форму з порожніми полями, показати помилки, виправити й зберегти.
4. Показати деталі кейса, відредагувати кількість годин, знайти зміну в списку.
5. Пояснити пошук, фільтр, сортування в URL, порожній результат і скидання.
6. Скасувати видалення, потім підтвердити видалення перевірочного кейса.
7. Показати тести (`npm run test:run`) і пояснити, що підміняється: `caseService` в інтеграційних тестах, `fetch` у тестах адаптера.
8. Показати `npm run preview`, результат вимірювання продуктивності й обмеження.

## Демонстраційні дані

Два початкові кейси з `src/data/cases.js` з'являються, коли ключ `daTrack.cases.v1` у localStorage відсутній. Відновити початковий стан: у DevTools → Application → Local Storage видалити лише цей ключ (не `localStorage.clear()`).

## Відомі обмеження

- Власного backend немає: працює режим mock (localStorage). API-адаптер підготовлено й перевірено лише тестами з підміненим `fetch`.
- Дані прив'язані до origin: інший порт дає інше сховище.
- Немає автоматичної синхронізації між вкладками та виявлення конфліктів редагування.
- Продуктивність у production-режимі не вимірювалась; для сотень кейсів потрібні пагінація або мемоізація.
- Розміщення на хостингу не перевірялось: для `BrowserRouter` потрібне правило повернення `index.html` для внутрішніх адрес.
